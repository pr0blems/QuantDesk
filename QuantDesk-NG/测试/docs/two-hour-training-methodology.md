# 两小时事件预测持续训练方法

## 固定目标

系统同时预测两种结果：

1. 两小时终点方向：预测时价格与两小时后价格比较。
2. 两小时有效事件方向：未来两小时先触及上涨动态阈值、下跌动态阈值，或无事件。

动态阈值只能使用预测时间之前的历史波动、点差和流动性计算。标签定义一旦产生版本，历史结果不得随模型调整而改写。

## 数据分层

- 可回溯基础层：OHLCV、成交笔数、主动买卖成交、时段和跨合约市场因子。
- 官方事件层：公司公告、监管披露、财报、宏观与商品定时发布。
- 舆情层：首次发现时间、来源数、传播速度、情绪分歧和异常账号比例。
- 微观结构层：5/20/50/100档深度、持续失衡、撤单率、价差和持仓量变化。

历史不存在的订单簿或舆情数据不得补造。缺失值必须有可见的数据可用性标记，并降低置信度。

## 训练周期

1. 每日追加原始数据和不可修改的预测结果。
2. 每周生成候选模型，使用滚动窗口训练。
3. 时间顺序切分为训练、概率校准、阈值选择和锁定测试四段，各段之间保留两小时隔离区。
4. 候选模型只有在锁定测试、分资产统计、置信度校准和漂移检查均通过后，才能替换当前模型。
5. 上线后继续影子验证；准确率、覆盖率或数据新鲜度越界时自动降级为“验证中”。

训练程序把每次结果保存在独立的 `candidates/<run-id>/` 目录。只有151个合约覆盖、有效事件样本、观察天数和80%事件精确率全部通过时，模型才会写入 `champion/`；失败的研究模型不会覆盖正式模型。

## 验收原则

- 151个合约全部进入预测与结果账本。
- 正式终点样本同一合约采用不重叠的两小时窗口。
- 同一新闻事件只有一条正式确认样本；初步、确认和延续版本分别留档。
- 有效事件方向精确率超过80%是硬目标，同时公开事件覆盖率和方向召回率。
- 全量终点方向公开总体、逐合约、逐资产和逐时段结果。
- 至少500个独立有效事件、20个市场日且每个合约有完成样本后，才能宣布正式通过。
- 训练段至少需要50个带完整预期差或等价结构化语义的事件；测试段事件不能反向用于补足这一门槛。

## 快速基线命令

安装研究依赖后运行：

```powershell
python -m pip install -e ".[research]"
$env:PYTHONPATH = "src"
python scripts/two_hour_research.py run --lookback-days 700 --sample-minutes 15
```

输出包括缓存数据库、锁定回测报告、两个校准模型和模型清单。研究产物默认位于 `data/` 与 `reports/`，不会提交到版本库。
