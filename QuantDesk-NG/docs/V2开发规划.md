# QuantDesk V2 开发规划

## 目标

构建面向多用户的 Binance Stocks Trading 量化交易系统，使用 MySQL/MariaDB 作为业务事实源，同时兼容手机浏览器、桌面浏览器以及后续 PWA/桌面壳。

当前单机版继续作为行情和策略原型；V2 在 `src/quantdesk_v2` 中独立开发，避免尚未验证的交易代码影响现有工作台。

## 已落地的第一阶段

- 环境变量配置，数据库密码不进入源码。
- `users` 表保存用户与加密后的 Binance API Key/Secret。
- `user_sessions` 保存轮换式刷新令牌的哈希，不保存明文令牌。
- `audit_logs` 记录注册、登录、密钥更新和删除等敏感操作。
- Argon2id 密码哈希、短期 JWT Access Token、Web HttpOnly Refresh Cookie、原生客户端 Refresh Token。
- 明确 CORS 白名单、安全响应头、请求体大小限制。
- Alembic 初始迁移和响应式 Web 外壳。

## 数据库现状与阻断项

- 连接地址、数据库名和用户通过 `.env` 配置，不写入源码。
- 数据库兼容 MySQL/MariaDB 协议。
- 当前业务表数量：0。
- TLS：服务器不支持 SSL，`require_secure_transport=OFF`。

在服务端启用 TLS、提供 CA 证书并设置 `require_secure_transport=ON` 前，不执行远程迁移，也不写入任何 Binance 用户密钥。

## 后续阶段

### 第二阶段：交易领域模型

增加 `instruments`、`instrument_rules`、`market_calendar`、`bars`、`strategy_versions`、`strategy_deployments`、`risk_policies` 和 `signal_events`。

### 第三阶段：可靠订单执行

增加 `order_intents`、`exchange_orders`、`order_events`、`fills`、`positions`、`balance_snapshots`、`ledger_entries` 和 `outbox_events`；实现唯一 `clientOrderId`、订单状态机、账户 WebSocket 和 REST 对账。

### 第四阶段：风控与灰度

实现用户级、账户级、策略级、标的级限额；加入每日亏损、最大回撤、行情过期、交易时段、碎股规则和全局 Kill Switch。依次经过 Paper、Shadow、人工确认、极小额 Canary。

## 手机与桌面兼容原则

- 后端使用版本化 JSON API；Web、PWA 和原生 App 共用同一接口。
- Web 使用 HttpOnly Refresh Cookie；原生 App 使用安全存储中的 Refresh Token。
- Access Token 生命周期短，刷新令牌每次使用后轮换。
- 响应式布局以 360px 手机宽度为最低目标，按钮触控高度至少 44px。
- 不在 Service Worker、LocalStorage 或页面 DOM 中保存 Binance API Secret。
- 交易确认、Kill Switch 和异常告警在手机与桌面端保持一致。
