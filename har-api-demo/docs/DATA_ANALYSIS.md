# 股票资讯接口数据分析

## 筛选结论

原始 HAR 中有 69 个去重接口、143 次 API 调用。本次仅保留能直接返回股票行情、证券新闻、股票社区内容或 IPO 数据的接口，最终得到 **26 个接口、69 次调用**；26 个接口在抓包中均取得业务成功响应。

盘口数据中，`/stock_info/ask_bid/blue-ocean/{symbol}?props=askBidDepth` 支持按证券代码查询。HAR 原始响应中的 PYPL，以及通过同一只读请求模板验证的 NVDA、AAPL，均包含 **卖 40 档 + 买 40 档**。Demo 已将三组响应脱敏后作为离线快照接入；指数 `.IXIC` 返回 `No quote data`，该接口也没有返回 100 档。

走势数据只捕获到 `/stock_info/time_trend/hour_trading_detail/{symbol}` 分时增量接口，请求值为 `period=day`、`beginTime=1787947140000`，响应 `items` 只有 1 条 `price/avgPrice/volume/time/amount` 数据；该结构不是 OHLCV K 线。社区 `/v1/order-sharing/candlestick` 虽有 `period=INTRADAY`，但属于晒单场景且响应为空。HAR 因此不能验证 M5、M15、M30、H1、日K、周K、月K 的服务端传值，也不能确定服务端最大条数。

Demo 已将图表改成七周期 OHLCV 离线样例：M5/M15/M30/H1/日K/周K/月K 分别生成 2000/1600/1200/900/504/260/120 根，单周期前端硬上限为 2,000 根；每次只绘制当前窗口 72 根并通过横向拖拽改变窗口，以控制 SVG 节点数量。该 2,000 根是 Demo 的前端容量设计，不是接口服务端上限。

新闻数据由 3 个 GET 接口组成：普通证券新闻、置顶新闻和实时/评级新闻。PYPL、NVDA、AAPL、`.IXIC` 均验证可按 `symbol/symbols` 返回数据；Demo 每个标的最多保留 24 条脱敏快照，并按新闻 ID 去重。

社区接口的市场态度统计仅返回 `tweetCount`，没有原始看多/看空百分比。Demo 因此直接使用接口讨论数和主题名称，并对每只标的最新 9–10 条帖子做关键词倾向分类；该比例在 UI 中标记为“内容倾向估算”，不能等同于全量社区投票。

已移除账户与认证、模拟持仓、通知红点、行情提醒、曝光统计、运营活动、客户端配置、地理定位和遥测上报等 43 个非股票资讯接口。

## 保留的数据类型

### 1. 行情数据（14 个）

- 股票详情、交易状态和扩展行情字段；
- 逐笔成交、成交价分布、买卖盘深度；
- 盘前盘后分时走势和延长时段排行；
- 指数成分、关联合约、公司行动与估值分析；
- 市场总览和关联行情栏。

主要服务：`hq2.skytigris.cn`、`hq-depth.skytigris.cn`。

### 2. 社区资讯（8 个）

- 股票最新讨论和推荐讨论；
- 交易晒单及对应 K 线；
- 市场态度统计；
- 股票每日摘要；
- 与证券关联的主题内容。

主要服务：`community-service.laohu8.com`。

### 3. 新闻资讯（3 个）

- 证券新闻聚合列表；
- 置顶新闻；
- 按证券或场景返回的新闻列表。

主要服务：`stock-news.laohu8.com`。

### 4. IPO 数据（1 个）

- IPO 标的及发行信息列表。

主要服务：`trade.skytigris.cn`。

## 数据接入特征

- 20 个 GET、6 个 POST；POST 主要承担行情详情、排行和主题内容查询。
- 26 个接口都观察到 Bearer Token，说明它们是客户端私有接口，并非无需认证的公开数据源。
- 不同服务的成功语义不统一，出现过 `ret=0`、`ret=200`、`code=200`、`code=62000000`、`code=91000000` 等形式。
- 业务参数主要是 `symbol`、`market`、`period`、分页和交易时段；版本、设备、地区等客户端上下文参数占比较高。
- 同一证券 `PYPL` 和指数 `.IXIC` 会并行请求行情、新闻和社区内容，说明客户端采用多服务聚合方式构建证券详情页。

## 使用边界

这些接口可用于离线结构研究、Mock、数据模型设计和合法账户下的兼容性分析。它们不等于公开或稳定 API；真实接入应优先选用服务方授权的开放接口。
