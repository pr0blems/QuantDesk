# QuantDesk V2 运行说明

## 开发环境

1. 从 `.env.example` 创建 `.env`。
2. 生成应用密钥：

   ```powershell
   python -m quantdesk_v2.cli generate-secrets
   ```

3. 将生成的 `JWT_SECRET` 和 `CREDENTIAL_MASTER_KEY` 写入 `.env`。
4. 安装依赖并迁移数据库：

   ```powershell
   python -m pip install -e ".[dev]"
   quantdesk-v2 check-db
   alembic upgrade head
   ```

5. 启动：

   ```powershell
   quantdesk-v2 serve
   ```

访问 `http://127.0.0.1:8200`。`start.bat` 和 `autostart.vbs` 也只启动该入口。

## 数据库架构

- 应用连接只允许 `mysql+pymysql` 或 `mariadb+pymysql`。
- Alembic 当前版本为 `0019_hedge_mode_live`。
- 用户、会话、审计、Binance/AI 模型加密凭据、策略、回测、行情、提醒、持仓和模拟盘数据统一存储在 MySQL/MariaDB。
- 每个用户首次登录会复制系统策略模板，模拟盘账户绑定用户自己的策略快照。
- 每个用户可在 `/settings` 的二级分类“API 凭证”中管理自己的 AI 模型；策略语义编辑优先使用该用户启用的默认模型。
- 应用只使用 MySQL/MariaDB 持久化业务数据，不读取本地数据库或共享密钥文件。
- 市场机会由系统共享扫描器生成；用户对机会的关注、忽略和提醒偏好保存到 `user_opportunity_states`，以 `user_id + opportunity_id` 隔离。

## Binance 实盘交易

- `/live` 位于“模拟盘”下方，复用策略快照和信号求值，但资金、持仓、挂单始终以 Binance 为准。
- 实盘与模拟盘使用同一份服务端 `tradfi_symbols.json` 品种池；创建实盘部署时不能由客户端改成 BTC、ETH 等加密币合约。执行前会按 Binance 当前 `TRADING` 状态过滤不可用品种，“最大持仓数”只限制并发仓位，不限制扫描品种数。
- 进程级总开关为 `BINANCE_LIVE_TRADING_ENABLED`；每个新实盘部署仍默认暂停，必须在页面输入完整部署名称并二次确认。
- 当前执行器支持标准 USD-M 单向持仓与双向持仓模式，不支持 Portfolio Margin；双向模式下每个策略订单与保护单都绑定 `LONG` 或 `SHORT`，且保护单使用明确数量，避免影响同品种另一方向。杠杆硬上限 20x、单笔保证金比例上限 10%、总保证金比例上限 50%。
- 普通市价单使用 Binance `/fapi/v1/order`，止损和止盈保护单使用 `/fapi/v1/algoOrder`；所有订单先写入 `live_order_intents` 幂等账本。
- 暂停部署只会阻止新的策略动作，不会自动平仓，也不会撤销用户在 Binance 上手工创建的订单。

## 测试数据库

测试绝不回退使用应用 `.env` 中的业务数据库。需要 MySQL 的集成测试必须显式提供以下配置之一：

- `QUANTDESK_TEST_DATABASE_ADMIN_URL`：管理员连接；测试会创建并最终删除唯一的 `quantdesk_test_*` 数据库。
- `QUANTDESK_TEST_DATABASE_URL`：预先建立、名称必须以 `quantdesk_test_` 开头的专用测试库。

未配置专用测试库时，纯单元测试照常执行，需要 MySQL 的集成测试会明确跳过。详细说明见 `tests/README.md`。

## 生产环境最低要求

- 设置 `APP_ENV=production`、`APP_COOKIE_SECURE=true`，并通过 HTTPS 对外服务。
- 设置 `ALLOW_PUBLIC_REGISTRATION=false`，通过受控流程创建用户。
- MySQL/MariaDB 开启 TLS，配置 `DB_SSL_REQUIRED=true`、`DB_SSL_VERIFY_IDENTITY=true` 和 `DB_SSL_CA`。
- 防火墙只允许应用服务器访问数据库 3306 端口。
- `JWT_SECRET`、`CREDENTIAL_MASTER_KEY` 和数据库密码由密钥管理系统注入；可选的 `OPENAI_API_KEY` 仅作为用户未配置默认模型时的服务端回退。
- `FINNHUB_API_KEY` 仅由服务端注入，用于读取美股 Market Status 和美股现货行情；不要把 Token 写入前端、URL 或提交到 Git。前端通过公开只读的 `/api/v2/market/us/status` 和 `/api/v2/market/us/quotes` 调用。
- Finnhub 美股行情使用一个服务端 WebSocket 连接订阅成交，REST Quote 按 `FINNHUB_QUOTE_POLL_SECONDS` 低频轮询补充快照。一个 API Key 只运行一个 WebSocket 采集器；多 API Worker 部署时应只在专用采集进程启用 `FINNHUB_WEBSOCKET_ENABLED`。
- `/monitor` 的 Binance TradFi 与 Finnhub 美股现货是两个独立页签、独立接口和独立缓存；任一数据源异常时都不会显示另一个市场的数据作为回退。
- `FINNHUB_WEBHOOK_SECRET` 必须与 Finnhub Dashboard 当前 Webhook Secret 完全一致。Webhook URL 为 `/api/v2/integrations/finnhub/webhook`；GET 只检查就绪状态，Finnhub 使用带 `X-Finnhub-Secret` 的 POST 投递事件。
- `Unusual Whales` 新闻 Token 以 Fernet 密文保存在 MySQL `admin_settings` 的 `integration_credential:unusual_whales` 记录中，采集器使用服务端 `CREDENTIAL_MASTER_KEY` 解密；数据库和管理接口都不返回明文。`UNUSUAL_WHALES_API_KEY` 仅作为旧部署的兼容回退。
- Binance API Key 禁止提现，仅授予读取和所需交易权限，并绑定应用出口 IP。
- 正式部署使用进程管理器运行 API 和后台 Worker，不使用旧版桌面 EXE。

## 管理后台

`/admin` 是与用户行情终端完全分离的管理应用，拥有独立页面、脚本、样式、登录入口和模块路由，
只对 `is_admin=true` 的账户开放。普通用户端不会加载管理端资源。首次部署可通过以下命令创建管理员，
密码只从进程环境读取，不写入命令参数或项目文件：

```powershell
$env:QUANTDESK_ADMIN_PASSWORD = "使用至少 12 位的独立强密码"
quantdesk-v2 create-admin --username admin
```

后台细分为运行总览、采集器、提醒事件、信号规则、舆情来源、合约数据、用户权限、存储维护和审计日志。
支持采集器心跳与暂停、信号规则热更新、新闻源新增/编辑/删除/启停/权重/限频/抓取测试、全局提醒和舆情检索、
合约行情覆盖检查、用户角色与会话管理、数据留存预览与清理。所有修改接口同时校验管理员角色与浏览器标签页用户身份，并写入审计日志。

当前开发环境的远程数据库尚未启用 TLS；切换生产环境前必须完成上述 TLS 配置。
