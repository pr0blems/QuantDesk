# QuantDesk V2 运行说明

## 开发环境

1. 复制 `.env.example` 为 `.env`，填写数据库密码。
2. 生成应用密钥：

   ```powershell
   python -m quantdesk_v2.cli generate-secrets
   ```

3. 将输出的 `JWT_SECRET` 和 `CREDENTIAL_MASTER_KEY` 写入 `.env`。
4. 安装依赖：

   ```powershell
   python -m pip install -e ".[dev]"
   ```

5. 数据库启用 TLS 后执行迁移：

   ```powershell
   alembic upgrade head
   ```

6. 启动：

   ```powershell
   quantdesk-v2 serve
   ```

访问 `http://127.0.0.1:8200`。V2 使用 8200 端口，不影响当前 8100 端口的桌面版本。

## 生产环境最低要求

- 使用域名和 HTTPS，`APP_COOKIE_SECURE=true`。
- 关闭公开注册（`ALLOW_PUBLIC_REGISTRATION=false`），由管理员创建首个账户并逐步接入邀请机制。
- MariaDB/MySQL 启用 TLS，并提供 `DB_SSL_CA`；禁止公网明文数据库连接。
- 数据库防火墙只允许应用服务器 IP，禁止向整个互联网开放 3306。
- `JWT_SECRET` 与 `CREDENTIAL_MASTER_KEY` 由密钥管理系统注入，不写入镜像或仓库。
- Binance API Key 禁止提现，只允许读取和所需交易权限，并绑定应用出口 IP。
- 使用进程管理器运行 API 与后台 Worker；不要依赖 `start.bat` 或桌面 EXE 提供多用户服务。

## 当前远程数据库的启用门禁

目前远程 MariaDB 不支持 TLS，因此只完成了只读连通性检查，没有执行迁移。服务器侧完成以下事项后再运行 `alembic upgrade head`：

1. 配置 CA、服务器证书和私钥，并开启 `require_secure_transport=ON`。
2. 防火墙仅允许生产应用服务器访问 3306。
3. 将 CA 公钥证书放到应用服务器，设置 `DB_SSL_CA` 和 `DB_SSL_VERIFY_IDENTITY=true`。
4. 运行 `quantdesk-v2 check-db`；成功后才允许迁移及用户录入 Binance API 凭据。

旧版 `config/api_keys.json` 与 `src/config/api_keys.json` 中的密钥不自动迁移。正式切换前应在 Binance 后台轮换旧密钥，录入 V2 后再安全移除旧文件。
