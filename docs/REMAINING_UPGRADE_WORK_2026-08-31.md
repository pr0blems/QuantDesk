### P2-2 模拟盘自动对账和漂移告警

**状态：已完成（2026-08-31）**

**已实现**

- 对账会扫描待投影/失败事实并自动重试。
- 检查持仓、平仓流水与来源成交事实的关联漂移。
- 某一账户恢复失败时只隔离该账户的新订单，其他账户继续运行。
- 隔离和恢复状态写入账户级 `user_states`，并只在状态变化时产生告警，避免每 5 秒重复告警。
- 迁移 `0075_paper_reconciliation` 新增独立余额 checkpoint、逐笔余额流水和账户对账状态；同一 `source_execution_id` 只能记账一次。
- 余额与 checkpoint 不一致、持仓/交易/流水来源漂移会阻断对应账户；权益时间序列陈旧只告警，不会静默覆盖历史值。
- paper worker heartbeat 已输出账户数、阻断数、告警数、pending/failed、漂移数和最后成功对账时间；单账户阻断不会伪装成整个 worker 离线。
- `quantdesk-v2 audit-paper` 提供只读审计；`quantdesk-v2 reconcile-paper --account-id ID --confirm` 只重放明确账户的 pending/failed 成交投影。
- 模拟账户重置已经改为单事务，同时重置成交、持仓、交易、余额 checkpoint、权益和对账状态。

- `audit-paper-history` 对迁移检查点两侧的 applied 事实生成 dry-run 报告，明确区分迁移前封存历史和可重放事实。
- `rebuild-paper-history --confirm` 只补建检查点之后、来源 JSON 完整且余额闭合的缺失流水；事实不完整、余额不闭合或已有流水冲突时拒绝执行。
- 迁移前缺少成交事实的余额只由 baseline checkpoint 封存，不依据兼容持仓反推伪事实。
- 权益缺失分钟会被识别并告警，下一次正常 tick 会继续写入；因缺少当时完整价格快照，历史权益缺口明确不伪造回填。

**验收条件**

- [x] 对账失败时只暂停对应模拟账户，不能影响其他用户账户。

### P3-2 完成“成交到保护”恢复闭环

**状态：已完成（2026-08-31）**

**目标链路**

```text
开仓成交事实
  -> 拉取新鲜账户快照
  -> observe_account_snapshot
  -> settle_reflected
  -> 安装止损/止盈保护单
  -> 查询交易所确认保护覆盖
  -> 更新本地保护状态
```

- `LiveExecutionRuntime` 在成交后刷新账户事实并通过 execution control settlement 结算风险预留。
- Execution Journal、risk reservation 和 `live_order_intents` 分别保存订单、结算和保护步骤的恢复检查点。
- 风险反射失败保留预留并强制账户进入待对账状态，禁止继续扩大仓位。
- `ProtectionService` 使用确定性 client order id 安装并核验止损/止盈；失败时请求对账并安全平仓或保持保护后人工复核。

**验收条件**

- [x] 不存在“订单已成交但本地不知道下一步做什么”的状态。
- [x] 重复恢复不会安装多组保护单。
- [x] `audit-live` 可只读检查 UNKNOWN、长期未决执行和本地未保护持仓。

- `StrategyRevision` 只表示不可变策略版本。

- `BacktestRun` 不再创建伪部署记录；当前 `api.py` 仍存在相关逻辑。
