# QuantDesk V2 数据库字典

数据库名：`binance`。所有业务时间字段统一保存 UTC 时间。Binance API Key 与 Secret 仅保存 Fernet 密文，任何日志和接口响应均不得保存或返回明文。

数据库中的全部表和字段均已通过 `0010_trading_schema_comments` 写入中文 `TABLE_COMMENT` / `COLUMN_COMMENT`；本字典与数据库内注释共同维护。

## users — 平台用户及其加密后的 Binance API 凭据

| 字段 | 类型 | 空值 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | 否 | 用户主键，自增 |
| username | VARCHAR(64) | 否 | 登录用户名，全局唯一 |
| email | VARCHAR(254) | 是 | 用户邮箱，全局唯一 |
| password_hash | VARCHAR(255) | 否 | Argon2id 登录密码哈希 |
| is_active | BOOLEAN | 否 | 账户是否启用 |
| is_admin | BOOLEAN | 否 | 是否为平台管理员 |
| binance_api_key_encrypted | TEXT | 是 | Fernet 加密后的 Binance API Key |
| binance_api_secret_encrypted | TEXT | 是 | Fernet 加密后的 Binance API Secret |
| binance_key_fingerprint | VARCHAR(16) | 是 | API Key 的 SHA-256 短指纹，仅用于识别 |
| binance_key_version | INT | 否 | 凭据版本号，每次更新或删除递增 |
| binance_permissions | JSON | 是 | API 权限快照，只允许 READ 和 TRADE |
| binance_key_updated_at | DATETIME | 是 | Binance 凭据最后更新时间（UTC） |
| monitor_watchlist | JSON | 是 | 当前用户的合约监控自选列表 |

| created_at | DATETIME | 否 | 用户创建时间（UTC） |

索引：主键 `id`；唯一索引 `username`、`email`；普通索引 `is_active`。

## 行情、监控、实盘与模拟盘表 — MySQL 统一存储

| 表名 | 主键/租户键 | 用途 |
| --- | --- | --- |
| klines | symbol + tf + open_time（系统级） | 15m/1h/4h 历史 K 线，供所有用户的监控、回测和模拟盘共用 |
| ticker | symbol（系统级） | 最新价、24h 涨跌和成交额快照 |
| scores | symbol + tf + open_time（系统级） | 多周期多空评分及因子明细 |
| news | id（系统级） | 新闻、翻译、情绪和摘要 |
| social | symbol（系统级） | 全市场社交平台情绪快照 |
| system_state | k（系统级） | 行情采集、提醒事件去重和全市场舆情等真正的公共运行状态 |
| positions | user_id + symbol | 每个用户自己的 Binance 实盘持仓快照 |
| alerts | id；强制 user_id | 每个用户独立的监控提醒和已读状态 |
| user_states | user_id + k | 用户偏好、模拟盘信号游标等通用用户状态 |
| paper_accounts | id；唯一 public_id；强制 user_id | 用户创建的独立模拟盘实例，绑定同租户策略及策略快照 |
| paper_positions | id；唯一 paper_account_id + symbol；强制 user_id | 指定用户、指定模拟盘的当前持仓 |
| paper_trades | id；强制 paper_account_id + user_id | 指定模拟盘的已平仓成交 |
| paper_equity | paper_account_id + ts；强制 user_id | 指定模拟盘的独立权益曲线 |

`0008_mysql_market_store` 创建统一 MySQL/MariaDB 行情与交易存储；`0009_multitenant_trading` 增加租户外键和模拟盘账户层，并将旧的 `kv` 拆分为 `system_state` 与 `user_states`。模拟盘通过 `(paper_account_id, user_id)` 复合外键保证账户与用户一致；实盘持仓、提醒、模拟持仓、成交和权益查询都必须带租户键。应用不读取本地数据库文件。
