# QuantDesk Unusual Whales 行情与资金流升级计划

版本：1.1
日期：2026-08-16
实施快照：2026-08-16（以当前工作区代码为准）
适用项目：`D:\lianghua\src\quantdesk_v2`
适用模块：发现机会、AI 新闻研判、资金盘口指标、历史机会、预测统计分析、影子盘

## 1. 文档目标

本计划用于将 Unusual Whales 的实时行情、期权资金流、GEX、场内/场外成交、停牌和事件数据接入 QuantDesk，建立一条可回放、可审计、可降级的信号增强链路。

升级目标不是承诺盈利，而是：

1. 减少陈旧行情、宽价差、停牌和重大事件附近的错误入场；
2. 用个股期权资金流验证新闻与技术指标方向；
3. 用 GEX 和成交密集价位改善入场、止损、止盈与移动保护；
4. 区分“方向评分”和“是否可交易”，避免高分但不可成交；
5. 保存信号时点全部数据快照，支持无未来数据泄漏的历史回放；
6. 通过消融实验判断每类数据是否真正提升成本后期望收益。

在完成本文验收门槛前，新增数据只用于研究、虚拟预测和影子盘，不得自动触发实盘订单。

## 2. 当前基线与主要缺口

### 2.1 已具备能力

- 已建立 Unusual Whales REST 客户端、WebSocket 接收、事件标准化、批量入库和 REST 恢复链路；

- 报价缺失、报价陈旧、无效 NBBO、价差过宽、停牌及复牌冷静期已进入硬门控，关键数据缺失不会再默认视为通过；
- 已保存原始事件、分钟特征、风险事件、机会市场快照和门控决策，并记录 `feature_version`、`weights_version`、`decision_version`；
- 大盘模块已显示 NDX、SPX、DJI、RUT、VIX、板块、美股交易时段和开盘/收盘倒计时；
- 已支持盘前、盘中、盘后和休市状态，并将时段用于报价时效阈值；
- 已有新闻、技术指标、资金盘口、组合评分、评分历史、当前机会、历史机会和预测统计分析；
- 预测统计分析已支持每页 20 条、服务端分页、日期/股票/覆盖率/版本等筛选，以及冻结时点数据的因果消融对比；
- AI Monitor 已提供鉴权、租户隔离的 SSE 增量事件，前端使用局部刷新并保留较低频轮询作为回退；
- 管理后台已提供 Unusual Whales 服务端凭据、频道、阈值、权重、运行模式、连接健康、领导者和数据保留状态；
- Binance 映射合约价格继续作为研究预测的入场、持仓和结算价格来源。

### 2.2 当前缺口与降级边界

- `Market Tide` 当前可作为宏观快照和评分输入，但 5/15/30 分钟斜率、持续性、加速度和同一时段 Z-Score 尚未全部生产化；
- `Ticker Interval Flow`、`Net Flow`、GEX、Lit/Off-lit 等频道已具备接收、标准化和部分聚合能力，但上游套餐/频道可用性及字段完整度不一致；缺失时必须显示覆盖不足，不得插补成有效信号；
- GEX Levels、Off/Lit Price Levels 等低频数据可通过 REST 轮换补偿，但尚不能承诺每个监控股票、每一分钟都有完整快照；
- 当前 REST 恢复只能恢复“当前状态”，上游不提供游标时不能还原断线期间的每一笔高频成交；
- 宏观事件已具备风险事件模型和门控入口，但官方经济日历的全量覆盖、修订和生产时区校验仍需联调验证；
- 历史因果回放仅对同时具备信号时点不可变快照、特征和门控决策的样本可用；旧数据不允许用最新行情回填，UI 必须标记“不可消融/数据不足”；
- 当前消融面板用于研究比较，不能因单次回测改善就自动提升模块权重；样本外、成本后和影子盘门槛仍未完成；
- SSE 已用于页面增量更新，但生产环境代理超时、长连接稳定性、跨多实例发布和浏览器长时间运行仍需压力验证；
- WebSocket 单主实例、原始事件/特征保留清理和接管遥测已进入代码，仍需在目标线上多进程部署中验证；
- 现阶段仍为研究/影子链路，不具备“保证盈利”条件，也不得据此自动执行实盘交易。

## 3. 设计原则

### 3.1 分数与门控分离

方向评分回答“更偏多还是更偏空”，入场门控回答“现在能不能交易”。以下条件不得仅以加减分代替：

- 报价是否陈旧；
- 买卖价差是否可接受；
- 当前是否停牌；
- 是否临近高影响宏观事件或财报；
- 行情来源之间是否出现异常偏差；
- 是否存在足够流动性。

### 3.2 实时与历史使用同一特征定义

实时评分与历史回放必须使用同一套特征计算代码。历史回放只能读取信号时点之前已经产生的数据，不允许使用当天收盘后才能获得的汇总值。

### 3.3 原始数据、特征与决策三层分离

```text
原始事件层
  Price / Quote / Flow / GEX / Lit / Off-lit / Halt / Calendar
        ↓
特征层
  时效、价差、流向持续性、流向加速度、Gamma 距离、成交聚集、事件风险
        ↓
决策层
  方向评分、可交易门控、入场价格、止损、止盈、退出原因
```

### 3.4 失败安全

- 数据缺失不得默认为中性有效；
- 关键数据陈旧时不得产生“已触发”状态；
- WebSocket 断开时自动回退 REST，但必须显示数据来源和延迟；
- 无法确认数据质量时只保留研究候选，不进入影子盘。

## 5. 目标评分与门控模型

### 5.1 组合方向评分

第一版建议权重如下，最终权重必须通过滚动样本外验证确定：

| 评分域 | 建议权重 |
| --- | ---: |
| 新闻与七天历史研判 | 20% |
| 技术指标 | 30% |
| 个股期权资金流 | 20% |
| 宏观与板块环境 | 10% |
| GEX 与波动结构 | 10% |
| Lit/Off-lit 机构确认 | 10% |

```text
组合评分 =
  新闻研判分 × 0.20
  + 技术指标分 × 0.30
  + 个股期权流分 × 0.20
  + 宏观板块分 × 0.10
  + GEX 波动分 × 0.10
  + 机构成交分 × 0.10
```

缺少某一评分域时，不允许直接把缺失值当 50 分。必须：

1. 标记数据不可用；
2. 记录可用权重覆盖率；
3. 覆盖率低于门槛时降级为研究候选；
4. 只有经回测证明安全时，才允许对剩余权重归一化。

### 5.2 行情质量硬门控

初始建议阈值：

| 条件 | 盘中 | 盘前/盘后 |
| --- | ---: | ---: |
| `quote_age_ms` | ≤ 2,000 ms | ≤ 10,000 ms |
| `spread_bps` | 动态阈值，且不超过硬上限 | 使用更严格的信号分数和更小仓位 |
| 行情源价格偏差 | 低于动态阈值 | 低于更严格阈值 |
| 停牌 | 禁止入场 | 禁止入场 |
| 关键数据覆盖率 | ≥ 80% | ≥ 80% |

价差硬上限不能固定用于所有股票，应按股票流动性和时段计算最近 20 个同类时间窗口的分位数。

### 5.3 个股期权流评分

```text
期权流分 =
  方向性净权利金 30%
  + Ask/Bid 主动成交 20%
  + 资金流加速度 15%
  + 最近区间同向持续性 15%
  + Volume/OI 异常度 10%
  + 重复大单可信度 10%
```

触发要求：

- 最近 3 个有效区间至少 2 个与候选方向一致；
- 单笔脉冲不得独立触发入场；
- 多腿、临近财报和纯波动率结构必须降权或排除；
- Call、Put 类型不得直接等同于看多、看空；
- 优先使用 `all_opening`、Ask/Bid 成交位置、Bull/Bear 比例、DTE、Volume/OI 和重复成交类型判断。

### 5.4 Market Tide 改造

现有逻辑只读取最新值，升级后计算：

- 5 分钟、15 分钟、30 分钟方向；
- 最近 6 个点的线性斜率；
- 净权利金加速度；
- 同向持续点数量；
- 当前值相对过去 20 个交易日同一时段的 Z-Score；
- 与 NDX、板块和个股方向的共振/背离。

### 5.5 GEX 与退出价格

- 做多接近 Call Wall 时降低追涨分；
- 做空接近 Put Wall 时降低追空分；
- Gamma Magnet 可作为第一目标或吸附风险提示；
- Gamma Flip 附近降低仓位并提高确认要求；
- 止盈优先设置在主要 GEX 价位之前；
- 止损结合 Put/Call Wall、ATR 和盘口流动性，不只使用固定百分比；
- 正/负 Gamma 环境对趋势或均值回归的解释必须作为待验证假设保存，不直接写死为盈利规则。

### 5.6 Lit/Off-lit 使用规则

- 计算 Off-lit 成交额占 ADV 的比例；
- 检测价格附近的成交聚集和重复打印；
- 判断聚集价位是否被场内价格确认；
- 暗池大单本身不直接判多空；
- 未获得后续场内确认时只增加“机构关注度”，不增加方向分。

### 5.7 事件门控

初始规则：

- CPI、PCE、非农、FOMC 等高影响事件前 30 分钟禁止新触发；
- 数据发布后至少等待 5～15 分钟，再根据价差和波动恢复；
- 个股财报前后使用独立规则；
- 停牌复牌后设置冷静期，且重新计算全部指标；
- 事件风险必须冻结在信号快照，历史回放不得使用事后修订值替代当时可见值。

## 6. 数据架构

### 6.1 接收链路

```text
Unusual Whales WebSocket
  → 连接管理器
  → 事件校验与标准化
  → 去重与顺序检查
  → 内存/Redis 滚动窗口
  → 1 分钟特征聚合
  → 批量写入线上数据库
  → 机会扫描与实时评分

REST
  → 服务启动快照
  → WebSocket 重连后的缺口补偿
  → GEX Levels / Calendar / VIX / Price Levels 等低频数据
```

### 6.2 WebSocket 服务要求

- 单独后台服务运行，不占用 API 请求线程；
- 自动重连、指数退避、心跳和订阅恢复；
- 记录最后事件时间和最后接收时间；
- 识别重复事件、乱序事件和时间倒退；
- 连接恢复后先用 REST 获取当前快照，再继续增量流；
- 原始高频事件批量写库，禁止每条事件同步提交线上数据库；
- 达到积压上限后按数据等级丢弃低价值明细，但不得丢弃 Halt 和状态事件；
- 前端只读取后端聚合结果，不直接持有第三方令牌。

#### `market_stream_events`

- `size_imbalance`

- GEX 关键价位与当前位置；
- 大盘/板块/个股期权流共振或背离；
- 事件风险和停牌状态；
- 数据覆盖率；
- “为什么可交易/为什么未触发”明细；
- 评分变化中各评分域的贡献。

资金盘口弹窗新增：

- 价格与 Spread 走势；
- Call/Put 净流和加速度；
- GEX 关键价位；
- Lit/Off-lit 成交聚集；
- 数据更新时间、来源和是否降级。

预测统计分析新增筛选：

- 是否通过行情质量门控；
- 期权流分数区间；
- GEX 环境；
- 是否处于事件窗口；
- 数据覆盖率；
- 是否有 Lit/Off-lit 确认；
- 特征版本、权重版本和决策版本。

## 8. UI 升级方案

### 8.1 UI 升级目标

本次 UI 不是把所有接口字段直接堆到页面，而是解决以下产品问题：

1. 用户能在 3 秒内判断当前信号处于候选、可触发、已触发、持仓、受阻还是已退出；
2. 用户能明确看到“方向判断”和“是否允许入场”是两套不同结论；
3. 用户能看到实时价格、计划入场价、实际触发价、止损、止盈和当前收益，避免重复价格；
4. 用户能看到评分为什么变化，以及哪类数据正在支持或反对当前方向；
5. 用户能识别数据是实时、延迟、陈旧还是降级，避免将旧数据当成实时证据；
6. 页面增量更新，不因定时刷新整页闪烁、滚动跳动或弹窗重置；
7. 当前机会、历史机会和预测统计分析使用同一术语、状态和颜色语义。

### 8.2 页面信息架构

发现机会页面按四层信息组织：

```text
┌─────────────────────────────────────────────────────────────────┐
│ 页面标题   美股交易时段/开盘倒计时   数据源健康   最后更新时间 │
├─────────────────────────────────────────────────────────────────┤
│ 大盘环境：NDX / SPX / DJI / RUT / VIX / Market Tide / 事件风险 │
├─────────────────────────────────────────────────────────────────┤
│ 当前机会 / 历史机会      状态分组      多空数量      筛选/排序 │
├─────────────────────────────────────────────────────────────────┤
│ 机会卡片：状态 → 门控 → 交易计划 → 证据 → 实时结果             │
└─────────────────────────────────────────────────────────────────┘
```

桌面端保留双列机会卡片；窗口宽度不足时自动切换为单列。页面使用整体滚动，不在机会列表内部制造第二条纵向滚动条。

### 8.3 页面顶部状态区

右上角统一显示：

- 当前美股时段：盘前、盘中、盘后、休市；
- 距离开盘或收盘的倒计时；
- Unusual Whales WebSocket 状态：实时、重连中、已降级；
- 最后事件时间和端到端延迟；
- 高影响事件倒计时；
- 数据覆盖率。

状态展示规则：

| 状态 | 标签 | UI 行为 |
| --- | --- | --- |
| 实时 | 绿色“实时” | 正常增量更新 |
| 轻微延迟 | 黄色“延迟 X 秒” | 保留展示，门控按阈值判断 |
| 陈旧 | 红色“数据陈旧” | 禁止触发，并固定显示阻断原因 |
| 降级 | 灰色“REST 降级” | 显示数据来源，降低刷新频率 |
| 断开 | 红色“数据中断” | 停止新触发，不清空最后快照 |

禁止使用“加载中”覆盖整块页面。首次进入可显示骨架屏，后续刷新只更新发生变化的字段。

### 8.4 宏观大盘面板

宏观面板保留横向紧凑布局，并新增两种模式：

- 默认摘要：指数、VIX、Market Tide、板块方向、事件风险；
- 展开详情：指数 RSI、板块 Tide、VIX 期限结构、经济事件和数据来源。

摘要区每项显示：

- 当前值和涨跌幅；
- 当前时段；
- 数据更新时间；
- 对做多/做空机会的影响方向；
- 是否由实时源或降级源提供。

重大事件在面板上方使用整页风险条：

```text
⚠ 距离 CPI 发布 18 分钟：暂停新入场，现有机会继续监控
```

风险条可收起但不能完全隐藏；进入阻断窗口时所有机会卡片同步显示“事件门控未通过”。

### 8.5 当前机会的标签与状态分组

当前机会页签下增加统一状态筛选：

| 分组 | 定义 |
| --- | --- |
| 全部 | 当前未结束的全部机会 |
| 候选 | 新闻成立，但其他门控尚未全部通过 |
| 条件满足 | 全部门控通过，正在等待触发价格 |
| 已触发 | 已建立虚拟预测或影子持仓 |
| 受阻 | 因陈旧行情、停牌、事件、价差或冲突而禁止入场 |
| 数据异常 | 数据覆盖不足、乱序、来源冲突或计算失败 |

每个页签显示总数及多空分布，例如：

```text
已触发 17（多 12 / 空 5）
受阻 4（行情 2 / 事件 1 / 停牌 1）
```

默认排序规则：

1. 已触发持仓；
2. 条件满足；
3. 候选；
4. 受阻；
5. 同一状态内按最近状态变化时间倒序。

用户可切换为信号时间、组合评分、实时收益或数据质量排序。切换页签和筛选条件时保留页面滚动位置。

### 8.6 机会卡片重构

每张卡片分成五个区域。

#### A. 标题与核心状态

显示：

- 股票名称、映射合约；
- 做多/做空；
- 当前生命周期状态；
- 当前组合分、变化箭头和变化值；
- AI 分析结论按钮；
- 数据新鲜度标签。

组合分示例：

```text
↑ 76.8   +3.4
当前组合分 · 5 分钟内变化
```

点击组合分打开评分走势弹窗。不得再使用“首个点”代替真实变化；如果只有一个采样点，应明确显示“样本不足，暂无趋势”。

#### B. 入场门控条

门控按固定顺序展示：

1. 新闻方向；
2. 策略组；
3. 技术评分；
4. 个股期权流；
5. 大盘/板块共振；
6. GEX 位置；
7. 行情质量；
8. 事件/停牌；
9. 盘中冲突。

每项使用图标、文字和结果，不只依赖颜色：

```text
✓ 期权流  同向 82.4
× GEX     接近 Call Wall
! 行情    延迟 3.2 秒
```

鼠标悬停显示计算时间、来源、阈值、当前值和判定原因。数据不可用显示“无数据”，不得显示成“通过”。

#### C. 交易计划与实时结果

等待触发时显示：

- 计划方向；
- 计划触发条件；
- 当前参考价；
- 计划触发价；
- 预估止损、止盈；
- 风险收益比；
- 等待有效期。

已触发后改为：

- 触发时间；
- 实际触发价；
- 当前实时价格；
- 当前毛收益率和 10 倍杠杆收益率；
- 估算手续费、滑点、资金成本；
- 当前净收益率；
- 当前止损、止盈和移动保护价；
- MFE、MAE；
- 退出状态或退出原因。

禁止在“参考价、触发价、买入价”三个位置重复显示同一个值。等待触发和已触发使用不同信息结构。

#### D. 关键市场证据

卡片默认只展示最重要的 4～6 项：

- 期权净流方向及持续区间；
- Market Tide 共振/背离；
- Gamma Flip、Call Wall、Put Wall 的最近距离；
- Off-lit 成交聚集价；
- Spread 和 Quote Age；
- 下一项重大事件。

其余证据通过“另有 N 项”展开，不让卡片高度无限增长。

#### E. 新闻与更新时间

- 默认显示最多 2 条直接关联新闻；
- 相同事件聚类后只展示主新闻；
- 显示新闻置信度和与股票的关联度；
- 显示发现时间、最后评分时间、最后行情时间；
- 历史研判、新闻分析记录从 AI 分析弹窗查看。

### 8.7 卡片状态视觉规范

| 状态 | 主色 | 左边框 | 主要文案 |
| --- | --- | --- | --- |
| 候选 | 黄色 | 黄色细线 | 等待更多确认 |
| 条件满足 | 紫色 | 紫色细线 | 条件满足，等待触发价 |
| 已触发做多 | 青绿色 | 青绿色实线 | 已触发做多 |
| 已触发做空 | 红色 | 红色实线 | 已触发做空 |
| 受阻 | 橙色 | 橙色虚线 | 已阻断：具体原因 |
| 数据异常 | 灰红色 | 灰红色虚线 | 数据异常，不参与触发 |
| 已退出 | 灰色 | 灰色细线 | 已退出：具体原因 |

做多、做空只能表示方向，不能代替生命周期状态。例如“做多 + 受阻”和“做多 + 已触发”必须是两个不同标签。

### 8.8 评分走势弹窗

评分弹窗升级为多维时间序列：

- 组合分；
- 新闻研判分；
- 技术指标分；
- 个股期权流分；
- 宏观/板块分；
- GEX/波动分；
- Lit/Off-lit 确认分；
- 入场门槛线和实际触发点。

底部明细表增加：

- 计算时间；
- 各评分域数值；
- 相比上次的变化；
- 变化最大的因素；
- 数据覆盖率；
- 是否通过硬门控；
- 当时行情价格。

折线图只使用真实采样点；不使用两点之间生成的虚假插值作为评分证据。缺口时在图上断线并标记数据中断。

### 8.9 资金盘口详情弹窗

新增独立“资金盘口”详情页签，采用四块布局：

#### 1. 行情与盘口质量

- Last、Bid、Ask、Midpoint；
- Spread 与 Spread Bps；
- Bid/Ask Size、Size Imbalance；
- Quote Age；
- 盘前/盘中/盘后；
- 价格源偏差。

#### 2. 个股期权资金流

- 5m/15m/30m 净 Call、净 Put、净方向；
- 连续同向区间；
- 资金流斜率和加速度；
- Ask/Bid 主动成交比例；
- Opening、Sweep、Volume/OI、DTE；
- 多腿交易占比和降权说明。

#### 3. GEX 与关键价位

- 当前价格；
- Call Wall、Put Wall、Gamma Flip、Gamma Magnet；
- 当前价格到各价位的距离；
- 对当前方向的支持、阻力或风险；
- 建议止盈止损参考，但明确标记为研究建议。

#### 4. Lit/Off-lit

- 场内/场外成交额；
- Off-lit/ADV；
- 价格聚集区；
- 聚集后是否获得场内价格确认；
- 明确提示“场外成交本身不直接代表多空”。

### 8.10 AI 分析结论弹窗升级

左侧页签调整为：

1. 基本面信息；
2. 相关新闻列表；
3. AI 新闻分析记录；
4. 资金盘口指标；
5. 市场与 GEX；
6. AI 分析结论。

AI 最终结论页增加“数据输入覆盖”区：

- 是否使用了七天历史研判；
- 是否使用了当前持仓状态；
- 是否使用了个股期权流；
- 是否使用了大盘/板块环境；
- 是否使用了 GEX；
- 是否使用了 Lit/Off-lit；
- 缺失或陈旧的数据项。

最终结论必须将信息分为：

- 方向判断；
- 主要支持依据；
- 主要反对依据；
- 与上次判断相比的变化；
- 当前是否允许触发；
- 如果不允许，阻断原因；
- 结论有效期。

顶部继续保留“系统提示词配置”“历史研判”“新闻分析逻辑”按钮；模型审计弹窗必须能查看实际发送提示词、历史上下文摘要和模型原始返回，但敏感令牌必须脱敏。

### 8.11 历史机会 UI

历史机会只展示尚未最终结算或需要解释的历史生命周期记录，并增加状态筛选：

- 等待结算；
- 已触发待退出；
- 行情待补；
- 退出完成待统计；
- 数据异常。

每张历史卡片显示：

- 信号时点冻结评分；
- 信号时点市场、期权流和 GEX 快照；
- 实际触发价、退出价、止盈止损；
- 预计结算时间和等待原因；
- 当前数据补齐进度；
- 不再显示最新实时评分冒充历史评分。

### 8.12 预测统计分析 UI

顶部统计区增加：

- 全样本、有效样本、因数据门控被拒绝的样本；
- 多空分布；
- 成本后命中率；
- 平均毛/净收益；
- Profit Factor；
- MFE/MAE；
- 最大回撤；
- 各数据模块的覆盖率。

筛选器增加：

- 日期范围；
- 股票与板块；
- 方向；
- 交易时段；
- 新闻、技术、期权流、GEX、机构成交、组合分区间；
- 行情质量是否通过；
- 是否临近事件；
- 是否由停牌/陈旧行情阻断；
- 退出原因；
- 特征、权重、决策版本。

新增“消融对比”面板：

```text
基线
基线 + Quote/Halt
基线 + Quote/Halt + Option Flow
完整策略
```

对比命中率、净期望、Profit Factor、覆盖率和最大回撤，明确展示提升是否来自减少信号数量。

列表每页 20 条，服务端分页；排序、筛选和页码写入 URL 状态，刷新后保持。

### 8.13 管理后台 UI

管理后台增加“市场数据与信号门控”页面：

- Unusual Whales 凭据：只显示是否已配置和末四位，不回传完整值；
- REST、WebSocket 健康状态；
- 各频道启用开关；
- 当前连接数、最后消息时间、延迟和错误率；
- Quote Age、Spread、事件窗口等阈值；
- 各评分域权重；
- 当前 `feature_version`、`weights_version`、`decision_version`；
- 只记录/参与评分/硬门控三种运行模式；
- 一键退回仅记录模式；
- 修改人、修改时间和变更审计。

普通用户只能查看数据健康和当前生效版本，不得修改全局第三方数据配置。

### 8.14 异步更新与防闪烁

前端刷新策略：

- Price、Quote、评分和持仓使用后端 WebSocket/SSE 增量推送；
- 当前机会列表使用稳定 `opportunity_id` 定位并局部更新；
- 不重新构建整个卡片 DOM；
- 新项目插入时保留滚动位置，提供“有 N 条新机会”提示，由用户决定是否跳到顶部；
- 数值变化使用 300～500ms 轻量高亮，不使用整块闪烁；
- 用户正在查看弹窗时，只更新数据，不重置当前页签和滚动位置；
- 断线后保留最后数据并加陈旧遮罩，不清空页面；
- 高频价格最多每 250～500ms 合并渲染一次，评分按真实计算完成事件更新。

### 8.15 字体、密度与可访问性

- 页面正文最小字号 14px；
- 次要时间和来源最小字号 12px，颜色对比必须可读；
- 核心价格、收益、状态和评分使用 16～22px；
- 紧凑化优先减少空白和重复字段，不通过缩小字体实现；
- 红绿以外同时显示箭头、正负号和文本；
- 关键按钮可通过键盘访问；
- 弹窗支持 Esc 关闭并恢复焦点；
- Tooltip 不能是查看关键阻断原因的唯一入口，移动端需可点击展开。

### 8.16 前端接口契约

机会列表接口至少返回：

```json
{
  "state": "candidate|ready|triggered|holding|blocked|data_error|exited",
  "state_changed_at": "RFC3339",
  "score": 76.8,
  "score_delta": 3.4,
  "score_components": {},
  "gate_summary": {},
  "quote": {},
  "option_flow": {},
  "gex": {},
  "institutional_flow": {},
  "macro_context": {},
  "risk_events": [],
  "trade_plan": {},
  "position": {},
  "data_quality": {},
  "feature_version": "",
  "weights_version": "",
  "decision_version": ""
}
```

前端不得根据显示文字反推状态，所有筛选、颜色和按钮权限均使用稳定枚举值。

### 8.17 UI 验收标准

- 用户无需打开弹窗即可识别信号状态、方向、组合分、触发价、实时价、止盈止损和当前收益；
- 等待触发和已触发卡片不再出现三个重复价格；
- 所有阻断信号都能显示具体阻断条件、阈值、当前值和时间；
- 数据陈旧或断线时页面不清空、不闪烁且不会继续触发；
- 评分弹窗能够解释每次分数变化；
- 历史机会显示信号时点冻结数据；
- 预测统计分析支持服务端分页，每页 20 条；
- 页面整体滚动，不出现机会列表局部纵向滚动；
- 高频更新期间卡片顺序只在用户选择的排序规则要求时变化；
- 1440p、1080p 和常见笔记本宽度下均无字段遮挡；
- 所有新增状态均具备空数据、加载、错误、降级和无权限展示。

### 8.18 当前 UI 实装状态

状态定义：

- **已实现**：当前代码已有完整数据契约和主要交互，可进入回归测试；
- **降级可用**：已有界面和数据，但第三方覆盖、旧样本或连接状态不足时会明确降级；
- **待验证**：代码已经接入，仍需在目标线上环境完成长时间、跨实例或真实数据验证；
- **待开发**：本文定义的目标形态尚未全部落地。

### 8.19 UI 开发任务拆分与验收顺序

为了避免“后端字段已接入但页面无法解释”的情况，UI 按以下顺序交付：

1. **契约先行**：先固定机会状态、门控、数据质量、版本和实时事件枚举；未知枚举必须显示“未知状态”，不能静默归入候选；
2. **安全态优先**：先完成陈旧、停牌、宽价差、事件阻断和数据缺失，再开发新的分数装饰；
3. **卡片局部更新**：以 `opportunity_id` 作为稳定键，只替换价格、评分、门控和持仓字段；不得通过清空列表重新渲染制造闪烁；
4. **历史冻结**：历史卡片、统计列表和消融面板只读取冻结快照，缺失时显示不可用原因；
5. **筛选可复现**：日期、股票、方向、覆盖率和版本进入 URL；后端回显生效筛选，导出与屏幕结果必须一致；
6. **降级演练**：分别断开 SSE、WebSocket、REST 和数据库只读连接，确认页面保留最后数据、显示陈旧状态且停止新触发；
7. **视觉回归**：在 2560×1440、1920×1080、1366×768 以及 125%/150% 缩放下检查遮挡、滚动、弹窗和字体；
8. **可访问性收尾**：补全键盘操作、焦点管理、ARIA 名称、颜色对比和减少动态效果偏好。

每个 UI 任务必须同时提供正常、空数据、加载、接口错误、无权限、数据陈旧和 REST 降级截图或自动化断言，不能只验收“有完整实时数据”的理想状态。

## 9. 分阶段开发计划

### M0：数据契约与功能开关

目标：为后续接入建立安全边界。

- 定义统一事件、时间戳、来源、时效和质量字段；
- 增加数据库迁移；
- 管理后台增加数据模块开关和健康状态；
- 第三方令牌继续只保存在服务端管理配置，日志和前端不得输出；
- 增加 `uw_quote_gate_enabled`、`uw_flow_enabled`、`uw_gex_enabled`、`uw_offlit_enabled` 等功能开关；
- 先保持全部新增特征为“仅记录，不影响决策”。

验收：数据库可重复迁移；开关关闭时现有系统行为完全不变。

### M1：行情质量、价格流与停牌

目标：先减少不可交易信号。

- 接入 Price WebSocket；
- 启用 Stock Quote 门控；
- 接入 Trading Halts；
- 保存 Quote 时效、Spread、盘口不平衡和时段；
- 更新当前机会实时价格、盈亏和止盈止损；
- 增加断线恢复和 REST 回退；
- UI 显示门控原因。

验收：停牌股票不产生新触发；陈旧/宽价差行情不会显示已触发；断线不产生重复事件。

### M2：个股期权资金流与 Market Tide

目标：给新闻和技术方向增加实时资金确认。

- 接入 Ticker Interval Flow、Net Flow；
- 将 Market Tide 改为 WebSocket 增量加 REST 补偿；
- 计算持续性、斜率、加速度和同一时段 Z-Score；
- 将期权流作为独立评分域；
- 保存每次评分的原始证据和特征版本；
- 完成做多、做空独立校准。

验收：单笔大单不能独立触发；同一输入可重复得到相同评分；历史回放与实时特征一致。

### M3：GEX、Lit/Off-lit 与退出优化

目标：改善入场价格和盈利保护。

- 接入 GEX WebSocket 和 GEX Levels；
- 接入 Lit/Off-lit 流与价格级别；
- 生成关键价位、距离和机构聚集特征；
- 将止盈、止损与 Gamma/成交密集价位联动；
- 保留 ATR 安全上限，防止关键价位异常过远；
- 为已触发机会持续更新退出建议，但不覆盖入场快照。

验收：历史统计可区分固定退出、GEX 退出和移动保护；不存在使用未来 GEX 值回填历史信号的情况。

### M4：宏观事件、VIX 期限结构和板块流

目标：建立全局风险环境。

- 接入 Economic Calendar；
- 接入 VIX Term Structure；
- 评估 Sector Tide、ETF Tide 和 Options Pulse；
- 建立重大事件前后阻断；
- 按盘前、盘中、盘后使用不同阈值；
- 将宏观、板块和个股共振显示在机会卡片。

验收：高影响事件窗口可以稳定阻断新触发，并在事件后按数据质量自动恢复。

### M5：回测、消融、校准和影子运行

目标：证明新增数据是否产生成本后优势。

依次运行：

1. 现有基线；
2. 基线 + Quote/Halt 门控；
3. 再加个股期权资金流；
4. 再加 GEX；
5. 再加 Lit/Off-lit；
6. 再加宏观事件和 VIX 结构；
7. 完整策略。

每一组分别统计：

- 样本数量与信号覆盖率；
- 成本后命中率；
- 每笔平均/中位净收益；
- Profit Factor；
- MFE、MAE；
- 最大回撤；
- 多空、时段、股票、板块、月份分布；
- Brier Score 与评分校准误差；
- 95% 置信区间；
- 双倍成本压力测试结果。

验收：只有样本外结果显著优于基线的数据模块才能进入正式评分。无效模块保留展示或直接关闭。

## 11. 上线与回滚

### 11.1 上线顺序

```text
仅采集
  → 仅展示
  → 评分旁路对比
  → 研究信号生效
  → 影子盘
  → 模拟盘
  → 满足独立准入后再评估微型实盘
```

### 11.2 灰度要求

- 初期只对 5～10 个高流动性股票启用；
- 按股票和评分域独立开关；
- 新旧评分同时保存，不覆盖旧版本；
- 新策略触发异常率、数据延迟或缺失率超限时自动回退；
- 回退只关闭新增评分和门控，不删除历史快照。

### 11.3 运行监控

- WebSocket 在线状态；
- 每个频道最后事件时间；
- 端到端延迟 P50/P95/P99；
- 每分钟事件数和丢弃数；
- 重连次数；
- REST 限流与错误率；
- 数据库写入延迟；
- 各评分域覆盖率；
- 因门控被拒绝的信号数量与原因；
- 第三方数据成本和调用额度。

## 12. 验收门槛

### 12.1 工程验收

- 关键事件无重复写入；
- 停牌和陈旧行情门控覆盖率 100%；
- WebSocket 重连后能够补齐状态且不倒退时间；
- 所有机会均保存特征版本、权重版本、来源和时效；
- 前端不暴露第三方令牌；
- 单个第三方接口失败不会导致 AI Monitor 整体 500；
- 历史机会展示的是信号时点快照，而不是当前最新值。

### 12.2 策略验收

沿用项目现有实盘准入标准，并额外要求：

- 至少 1,000 条去重、已结算、成本后样本；
- 时间跨度不少于 180 天；
- 做多、做空各不少于 100 条；
- 成本后平均收益的 95% 置信区间下限大于 0；
- 样本外 Profit Factor 不低于 1.20；
- 双倍手续费和滑点下仍为正期望；
- 不得只由单只股票、单个月份或单一市场状态贡献利润；
- 新增模块相对基线的提升必须在样本外消融实验中成立；
- 完成至少 4 周影子运行和 100 笔同链路模拟成交；
- 任何门槛跌破时自动退回研究模式。

胜率不是唯一目标。即使命中率提高，如果盈亏比、回撤或成本后期望恶化，也不得通过验收。
