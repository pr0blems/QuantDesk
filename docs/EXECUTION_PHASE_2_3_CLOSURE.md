## 1. 本轮目标

第二、第三阶段只解决一件事：让回测、模拟盘、Shadow 和实盘共享同一套确定性策略语义与执行写入内核，运行模式之间只保留行情源、时钟、撮合模型和 Broker 的差异。

```text
MarketEvent
  -> StrategyDecisionService
  -> DecisionEnvelope
  -> Risk / PositionPolicy
  -> ExitPolicy
  -> OrderIntent
  -> ExecutionService
  -> Broker adapter
  -> Execution / Position facts
```

实盘的 Binance 下单、保护单、订单对账、持仓同步和异常恢复是基础设施适配能力，不得再包含一套独立的策略方向、周期或止盈止损判断。

## 6. 本轮工作包

### P2/P3-A：消除跨运行器私有依赖

1. 将账户策略求值、策略决策审计和入场快照提升为公共应用服务。
2. `paper_engine` 与 `live_engine` 仅通过公共服务调用。
3. `live_engine` 的退出价位直接使用领域 `ExitPolicy`，不再回调模拟盘函数。
4. 增加架构边界测试，禁止 `live_engine -> paper_engine` 回归。

### P3-B：删除绕过统一内核的旧写路径

1. 删除已停用的 Binance 市价单直连函数。
2. 删除已停用的保护单直连函数及其专用回滚函数。
3. 增加静态边界测试：运行器不得直接调用交易客户端的下单方法。
4. 保留只读查询、撤单与对账能力，直到对应应用服务完成迁移。

### P2-C：模拟盘事实对账

1. 建立从 Execution / Fill 到模拟持仓、余额和交易流水的幂等投影。
2. 增加启动时差异检测与修复任务。
3. 将兼容表明确降级为 Projection，而不是订单事实来源。

### P3-D：拆分实盘恢复能力

按顺序抽取：

1. `LiveOrderReconciliationService`
2. `LivePositionSyncService`
3. `ProtectionRecoveryService`
4. `LiveAccountRecoveryService`

每抽取一个服务，都先做行为等价测试，再删除 `live_engine` 中对应旧实现。不得一次性重写。

## 7. 一致性与故障验收矩阵

| 场景 | 回测 | 模拟盘 | Shadow | 实盘 Canary |
| --- | --- | --- | --- | --- |
| 多/空/观望方向 | 必须一致 | 必须一致 | 必须一致 | 必须一致 |
| 触发周期与信号有效期 | 必须一致 | 必须一致 | 必须一致 | 必须一致 |
| 初始止损、止盈 | 必须一致 | 必须一致 | 必须一致 | 允许交易所步长取整 |
| 最大持有与退出原因 | 必须一致 | 必须一致 | 必须一致 | 必须一致 |
| 手续费与滑点 | 模型值 | 模型值 | 模型值 | 交易所事实 |
| 重启重复订单 | 不适用 | 必须为 0 | 必须为 0 | 必须为 0 |
| UNKNOWN 恢复 | 不适用 | 必须闭环 | 必须闭环 | 必须通过交易所对账闭环 |
| 保护单部分失败 | 不适用 | 模拟故障 | 模拟故障 | 必须进入安全恢复，禁止静默裸仓 |

## 8. 上线与回滚规则

1. 本地修改、测试、提交并推送 Git。
2. 服务器只执行 `git pull --ff-only`，不得手改源码。
3. 数据库迁移先升级并核验当前 revision。
4. 先重启 API 和 Shadow / 模拟 worker，验证健康与幂等状态。
5. 实盘只对 Canary 账户启用；若出现重复意图、UNKNOWN 堆积、保护缺失或账户对账失败，立即停止扩大并回滚运行版本。
6. 旧代码只有在对应新服务通过验收后删除；UI 迁移不在本轮范围。
